# AIDA-11 · Audit Procedures และภาษาที่ไม่กล่าวหา
> ไฟล์: AIDA-11 | เวอร์ชัน: 1.0 | ส่วนหนึ่งของ AIDA Knowledge Pack
> ไฟล์นี้ตอบคำถาม: เมื่อได้ Finding แล้วควรทำ Audit Procedure อะไรต่อ, Interpretation ต้องตอบอะไรบ้าง, ควรเขียน Finding ด้วยถ้อยคำแบบไหน

## สรุปสั้น
ระบบแนะนำวิธีหาหลักฐานเพิ่ม ไม่ตัดสินแทนผู้ตรวจสอบ
Audit Procedures 8 ขั้นสร้างจาก Finding (gaps + hypotheses → Recommended procedures, AIDA-01 Stage 17)
Interpretation (Layer 7) เปลี่ยนผลเชิงเทคนิคเป็นภาษาที่ผู้ตรวจสอบและผู้บริหารนำไปใช้ได้ โดยไม่กล่าวหา

## Audit Procedures Generated from Findings
| # | Procedure | ทำอะไร | ตัวอย่าง |
|---|---|---|---|
| 1 | Validate Source | ตรวจ record, field, period, lineage และ completeness | ยืนยันว่ารายการมาจากระบบบัญชีงวดที่ถูกต้องและไม่ขาดหาย |
| 2 | Reperform | ทำซ้ำ calculation ด้วย configuration เดียวกัน | คำนวณ MAD ใหม่ด้วย Registry version เดิม |
| 3 | Corroborate | เปรียบเทียบ evidence จาก skill/แหล่งข้อมูลอื่น | เทียบกับใบรับของ/สัญญา |
| 4 | Inspect Context | ตรวจเอกสาร อนุมัติ เหตุผลทางธุรกิจ และข้อยกเว้น | ตรวจบันทึกอนุมัติข้อยกเว้น |
| 5 | Expand Scope | ขยาย entity / period / peer / relationship เมื่อเหมาะสม | ดู vendor ที่ใช้บัญชีธนาคารร่วมกัน |
| 6 | Human Inquiry | สอบถามและบันทึกคำชี้แจงอย่างเป็นกลาง | สัมภาษณ์ผู้รับผิดชอบกระบวนการ |
| 7 | Conclude | ผู้ตรวจสอบประเมิน sufficiency และ relevance ของหลักฐาน | สรุปว่าอธิบายได้ / ต้องรายงาน |
| 8 | Track Action | เชื่อม finding กับ management action และสถานะติดตาม | กำหนดผู้รับผิดชอบและวันครบกำหนด |

## Layer 7 · Interpretation — ต้องตอบ 5 เรื่อง
1. เกิดอะไรขึ้น
2. เหตุใดจึงสำคัญ
3. Potential Risk โดยไม่กล่าวหา
4. Recommended Audit Procedures
5. ข้อจำกัดและสิ่งที่ต้องพิสูจน์เพิ่ม

### Template การเขียน Interpreted Finding
```
ข้อสังเกต: <สิ่งที่พบ + entity + ช่วงเวลา>
ความสำคัญ: <ผลกระทบทางธุรกิจ> | Confidence: <ระดับ> | Materiality: <ระดับ> | Priority: <ระดับ>
Potential Risk: <ความเสี่ยงที่อาจเกิด>
Evidence: <source skill + data reference>
ข้อจำกัด: <สิ่งที่ข้อมูลยังบอกไม่ได้>
Procedure ที่แนะนำ: <ขั้นจาก 1–8>
```

## ข้อห้าม (Guardrails)
- ห้ามใช้ถ้อยคำกล่าวหา ใช้ "ความผิดปกติ" / "รูปแบบที่ควรตรวจสอบเพิ่มเติม" / "Potential Risk"
- ห้ามสรุปผล (Conclude) แทนผู้ตรวจสอบ
- ห้ามเปิดเผยชื่อบุคคลในระดับ Executive โดยไม่จำเป็น

### ตารางถ้อยคำ: หลีกเลี่ยง → ใช้แทน
| หลีกเลี่ยง | ใช้แทน |
|---|---|
| ผู้ขายรายนี้ทุจริต | พบรูปแบบการจ่ายเงินให้ผู้ขายรายนี้ที่ควรตรวจสอบเพิ่มเติม |
| พนักงาน X โกงเงิน | พบรายการที่บันทึกโดยผู้ใช้ X ซึ่งยังไม่มีเอกสารประกอบครบ |
| มีการกระทำผิดในการจัดซื้อ | พบความผิดปกติในกระบวนการจัดซื้อที่อาจเป็น Potential Risk |
| เป็นบัญชีม้า | บัญชีมีรูปแบบ Funnel Account ตามเกณฑ์ที่กำหนด |
| แบ่งรายการเพื่อหลบวงเงิน | พบรายการหลายรายการใกล้วงเงินอนุมัติในช่วงเวลาใกล้กัน |
| จงใจปลอมเอกสาร | เอกสารประกอบยังไม่สอดคล้องกับข้อมูลในระบบ |
| ผู้บริหารสมรู้ร่วมคิด | พบความสัมพันธ์ระหว่าง entity ที่ควรยืนยันกับข้อมูลทะเบียน |
| คะแนน ML สูง จึงทุจริต | คะแนน ML สูง จึงควรให้ผู้ตรวจสอบทบทวน |
| ยืนยันว่ามีความผิด | ผลการวิเคราะห์ชี้ว่าควรดำเนิน Audit Procedure เพิ่มเติม |
| Priority สูงแปลว่าผิดแน่นอน | Priority สูงหมายถึงควรได้รับความสนใจก่อน |
| ผู้กระทำความผิด | ผู้เกี่ยวข้องกับรายการ |
